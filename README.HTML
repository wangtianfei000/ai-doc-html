先讲一件最近让我血压升高的事。

上周让 ChatGPT 帮我写一份《订单系统重构技术方案》，30 秒后它吐了一大段 Markdown 给我。整体看起来挺像样，可拉到「整体架构」那一节，我血压瞬间飙起来——

它给我画了这么一张「ASCII 架构图」： 

+----------------+       +-----------------+       +----------------+
|   Web 前端     | ----> |   API 网关       | ----> |   订单服务     |
+----------------+       +-----------------+       +----------------+
                              |        |
                              v        v
                        +---------+ +---------+
                        | 用户中心 | | 商品中心 |
                        +---------+ +---------+

我盯着这堆加号横线看了半分钟，差点把咖啡喷在屏幕上。2026 年了，AI 还在用 1990 年代 BBS 论坛风的字符画给我画架构图。

把 ASCII 架构图发给客户，对方会以为你穿越了。

我心想算了，让它换 Mermaid 总行了吧？于是补一句：「请用 Mermaid 重画。」AI 乖乖换了一段 graph TD 给我。

我一拷贝到客户的飞书文档里——它原封不动地把 Mermaid 源码当成普通文字渲染了出来，长这样： 

graph TD
    A[Web前端] --> B[API网关]
    B --> C[订单服务]
    B --> D[用户中心]
    B --> E[商品中心]

客户那边发来一个微笑表情：「老王，这个图我看不太懂…」

最后一击是界面原型。我让 AI 设计一个「订单管理后台的列表页」，它给我返回了——

左侧为侧边导航栏（包含「首页」「订单」「商品」「设置」四项），顶部为搜索栏与用户头像，中间区域为订单列表表格，包含订单号、客户、金额、状态、操作五列…

一段干巴巴的文字描述。我读完只想问：图呢？

Markdown 不是不行，是它根本扛不动「技术文档」这三个字。

那一刻我突然想通了：错的不是 AI，错的是我们让 AI 用 Markdown 这个 1991 年发明的纯文本格式，去承载 2026 年的「图文 + 图表 + 原型 + 高亮代码」。

这就是今天要聊的事——该让 AI 换载体了。

一、AI + Markdown 的三大灾难现场

把刚才那场翻车归类一下，AI 用 Markdown 写技术文档时，必然会撞上这三堵墙：

1

灾难一：ASCII 字符画架构图

Markdown 没有原生画图能力，AI 又被规定只能输出纯文本，结果就是——它会用 + - | 给你硬画。 

+--------+      +--------+      +--------+
| Client | --->| Server | --->|   DB   |
+--------+      +--------+      +--------+

问题：等宽字体下勉强能看，非等宽字体或导出 PDF 后线条直接错位；4 层以上的层级关系画不出来；多分支汇合彻底失控；客户拿到只会反问"这是不是乱码？"

2

灾难二：Mermaid 在大多数地方就是一坨源码

AI 学聪明了，给你写 Mermaid。可问题是——Mermaid 不是 Markdown 的标准能力，只在 GitHub / GitLab / Typora 等少数地方会渲染。你把它复制到下面这些地方，立刻原形毕露：

飞书文档 ❌
企业微信 ❌
钉钉 ❌
微信公众号 ❌
Word ❌
语雀（默认）❌
大多数邮件 ❌
导出 PDF ❌

问题：客户、产品经理、甲方爸爸 99% 都不在 GitHub 里看文档。你交付的 graph TD 在他们眼里就是一段长得像代码的废话。

3

灾难三：界面原型？MD 根本装不下

Markdown 的语法集里压根没有「布局」这个概念——没 flex、没 grid、没绝对定位、没颜色控制、没交互。AI 想给你画原型只剩两条路：

  • 路 A：用文字描述——「左侧导航栏，右侧表格…」客户全靠脑补，沟通成本爆炸。
  • 路 B：让你打开 Figma——AI 写完 MD，你还要手动画图，那 AI 给你省的时间又赔回去了。

问题：技术方案最贵的部分往往就是「让产品/客户提前看到长什么样」。这件事 Markdown 一点忙都帮不上。

三堵墙的根因只有一句话：Markdown 是为「读」设计的，不是为「展示技术系统」设计的。

二、解法：让 AI 直接吐 HTML

既然 Markdown 三堵墙都过不去，那干脆换一个能装下所有内容的载体——单文件 HTML。一句话总结叫「三位一体」：

📐
第一位：HTML 容器

单文件 .html 装下所有内容，浏览器双击就能看，不依赖任何编辑器。

<!DOCTYPE html>
<html>...</html>
📊
第二位：Mermaid CDN

本地直接渲染成 SVG 图形，不再依赖外部平台。打开 .html 就是图，不是源码。

<pre class="mermaid">
  graph TD ...
🎨
第三位：Tailwind CSS

CDN 引入，AI 用类名直接写出真实可点击的界面原型，不用再开 Figma。

class="flex
bg-white shadow-lg"

四、5 分钟实操：让 AI 换个吐法

改造其实只有一个动作：修改你给 AI 的提示词。从「请生成一份 Markdown」改成下面这段：

4.1 给 AI 的新版提示词

markdown · prompt.md 
请用「三位一体」格式生成一份**单文件 HTML** 技术文档。

# 文档主题
[填写你的主题，如：订单系统重构方案]

# 必含章节
1. 项目背景
2. 整体架构图（用 <pre class="mermaid"> graph TD </pre> 真渲染，禁止 ASCII）
3. 核心模块时序图（Mermaid sequenceDiagram）
4. 关键代码示例（Python，Prism.js 高亮）
5. 上线流程图（Mermaid flowchart，含判断分支）
6. 管理后台原型页（直接用 Tailwind class，要真实可视化）

# 强制约束
- 单 .html 文件，零本地依赖
- Tailwind CSS v4 CDN + Mermaid v11 CDN + Prism.js 1.29 CDN
- 禁止用 ASCII 字符画架构图
- 内置 window.print() 函数支持一键导出 PDF
- 配色蓝紫为主，符合企业风

只输出 HTML 代码，不要任何解释。

把这段话扔给 GPT-4o / Claude，它会一次性吐一个 .html 文件给你。保存、双击、完事。

4.2 最小可运行骨架

如果你想自己手写一份打底，下面这 18 行就够：

html · minimal.html 
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>我的第一份三位一体文档</title>

  <pre class="mermaid">
    graph LR
      A[需求] --> B[AI 生成 HTML]
      B --> C[双击就能看]
  </pre>
  <script>mermaid.initialize({ startOnLoad: true });</script>
</body>
</html>

4.3 一键 PDF 的核心代码

javascript · 一键 PDF 
// 等字体和图表渲染完成后，再调用浏览器原生打印
function exportToPDF() {
  const ready = document.fonts.ready || Promise.resolve();
  ready.then(() => new Promise(r => setTimeout(r, 300)))
       .then(() => window.print());
}

七、看到这里你可能还有几个问题

Q1：AI 真的能一次吐一份完整 HTML 吗？
能。GPT-4o / Claude Opus / Gemini 1.5 都能一次输出 1000+ 行的 HTML，结构、Mermaid、Tailwind class、Prism 代码块全部到位。本文就是 AI 一次性生成的。
Q2：CDN 离线打不开怎么办？
把 Tailwind / Mermaid / Prism 三个 JS 文件下载到本地，把 <script src=> 改成相对路径，一次配置永久离线。
Q3：Mermaid 画不出复杂的多层架构图怎么办？
简单图用 Mermaid，多层等宽架构图直接用 Tailwind HTML 自己画（flex + grid 强制等宽对齐）。本文里的「订单后台原型」就是 Tailwind HTML 写的，根本不依赖 Mermaid。
Q4：客户的电脑没装浏览器怎么办？
……如果 2026 年还有这种客户，建议你换工作。

写在最后

回到开头。被 AI 用 ASCII 字符画劝退之后，我把提示词改成了「请生成单文件 HTML」。同一个 AI、同一个需求，5 分钟出方案，客户当场拍板。

不是 AI 不行，是你给它的画布太小了。

Markdown 是一个伟大的格式，它简单、纯文本、Git 友好——这些优点 HTML 一样不少。但是当你需要表达一个真实的技术系统：分层、流程、原型、交互、品牌色、可打印——Markdown 那套语法集，撑不起 2026 年 AI 的产出。

所以下次让 AI 写技术文档时，请把提示词最后一句改成：

请输出单文件 HTML，使用 Tailwind CSS + Mermaid + Prism.js，禁止 ASCII 架构图。

就这一句话，能省你一晚上加班。
